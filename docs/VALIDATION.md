The document stage adds 31 checks covering draft creation/retries, draft presentation scopes, stale saves, duplicate/foreign-owner attachments, byte digests, version fingerprints, issued-content protection and duplicate issue prevention. Acknowledgments require an exact version/fingerprint and explicit confirmation, retain original receipts on repeat, and cannot change the recorded name. Replacement issue retains old content, attachments and receipts. Withdrawal and discarded replacement drafts preserve history; withdrawn/outdated forms are rejected. Legacy pending documents receive an idempotent receipt, copies contain the saved evidence, cross-owner writes fail, and a concurrent issue/acknowledgment has only one winner.

## Limits

Live AI, NEISPUO, verified signature providers and managed-device enforcement were not tested or represented as connected. The optional WebMCP registrations previously could not be exercised because the browser did not expose modelContext; ordinary UI use does not depend on them. Browser persistence checks are complemented by isolated route tests because the internal anonymous preview is intentionally read-only.

These checks do not certify legal compliance, assessment validity or operational readiness. School membership and class/pupil authorization are implemented for the directory, connected text/file homework and inbox, lesson library and practice, current/term/annual-grade journal, attendance and school text documents. The original learning profile, practice, gradebook, file registry, messaging and document routes remain owner-private demonstrations. Institutional enrollment, guardian-verification procedures, retention/reconciliation and migration of those workflows remain future stages.
